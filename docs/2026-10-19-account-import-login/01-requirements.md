# 账户导入与在线登录修复需求

日期：2026-10-19。状态：需求基线，供本次修复实施与验收使用。

## 2. JSON 导入要求

### REQ-01：文件与文本识别

覆盖设置页的数据导入、账户管理中的文件导入和添加账户对话框的文本入口。各入口应共用格式识别规则，同时保留“恢复备份”和“校验凭证添加账户”的业务区别。

应支持现有导出格式，并兼容以下明确的账户载荷：单个账户对象、账户对象数组、`accounts` 数组包装、现有备份中的 `accounts` 键值映射，以及顶层或 `credentials` 内的凭证字段。`data` 数组包装作为兼容目标纳入验收。不得递归搜索任意 JSON 并把无关对象当成账户。

字段兼容目标包括 `accessToken` / `access_token`、`refreshToken` / `refresh_token`、`clientId` / `client_id`、`clientSecret` / `client_secret`、`authMethod` / `auth_method`；字段必须是合法类型，字符串应去除首尾空白。`provider`、区域、到期时间与身份字段保留有效来源；不同位置的字段冲突须有明确且可测试的处理规则。

识别结构和凭证有效性分别反馈：合法 JSON 不等于合法账户；合法账户结构不等于远端凭证有效。Social 与 IdC/OIDC 的必填字段按认证方式判断，不得把所有账户都强制要求 `clientId` 和 `clientSecret`，也不得将缺少 OIDC 必要字段的记录静默存成有效账户。

遇到 UTF-8 BOM、外层空白应正常处理；对完整 Markdown JSON 代码围栏提供兼容。JSON 语法错误必须说明原因；不能把解析失败的 JSON 降级为其他格式并显示误导性的成功结果。保留当前支持的非 JSON 导入形式，具体兼容边界在修复方案中约定。

### REQ-02：OIDC 批量粘贴

批量输入解析、预览数量、提交按钮数量和实际提交必须来自同一个解析结果。识别出的记录应先标准化，再逐条检查必填字段和认证方式，然后进入凭证校验及添加流程。

支持混合有效与无效记录；一条失败不阻断其他独立记录。每条失败关联原始序号或 JSON 路径，显示缺失字段、类型错误、重复、远端拒绝、超时等原因。界面不得回显完整凭证。

必须准确区分成功、失败、跳过/重复以及取消后尚未处理的记录；计数能够核对总数。重复规则基于现有账户标识与可用身份信息制定，重复输入不可误报为新增成功，也不可悄悄覆盖已有账户。

## 3. 在线登录要求

### REQ-03：授权后自动完成

覆盖 Builder ID、IAM Identity Center/SSO、Google 和 GitHub 的实际登录分支。Builder ID 设备授权使用 Token 轮询；Google/GitHub 使用自定义 URI 回调及授权码兑换；IAM SSO 使用本地 HTTP 回调及 PKCE 授权码兑换，界面轮询主进程的处理结果。三种机制分别验收，不能仅以是否收到自定义 URL 协议为成功依据。

启动登录后桌面端应显示当前状态和可操作的授权入口。浏览器完成有效授权后，当前登录会话必须自动进入兑换/获取账户信息、保存账户、刷新列表及显示完成状态的流程。每个会话最多完成一次；迟到、重复或属于旧会话的回调不得添加错误账户。

启动失败、浏览器打开失败、回调监听失败、用户拒绝、轮询失效、凭证兑换失败、账户查询失败和超时均应结束等待并显示原因。Social 回调应验证路径和 `state`；设备授权遵守服务端轮询间隔、`slow_down` 与到期时间。

### REQ-04：取消、重试与一致性

关闭对话框、取消登录、切换登录渠道和重试时，清理当前会话的监听、轮询、定时器及回调服务资源。取消之后的请求结果不得继续写入账户。新的登录会话不应被旧会话的清理动作终止。

正常授权成功时，完成事件不能因监听订阅时序、组件状态闭包或视图切换丢失。账户落库成功后才能显示“添加成功”；数据保存失败应保留可重试状态，并避免重复消耗一次性授权码。

## 4. 验收标准

| 用例 | 输入或操作 | 通过条件 |
| --- | --- | --- |
| AC-01 | 本项目完整导出备份再导入 | 账户可恢复；保留分组/标签关系，冲突定义不覆盖本地内容；简化凭证采用当前选定分组 |
| AC-02 | 单对象、顶层数组、`accounts` 数组、`accounts` 映射、`data` 数组 | 预览与提交识别相同数量，无无关对象误识别 |
| AC-03 | 扁平凭证、嵌套 `credentials`、camelCase/snake_case | 标准化正确，认证方式与 provider 不被错误覆盖 |
| AC-04 | BOM、空白、完整 JSON 代码围栏 | 合法载荷识别成功；不完整或错误 JSON 显示解析错误 |
| AC-05 | 空数组、无关 JSON、缺字段、错误类型 | 不写入无效账户，错误定位到原记录和字段 |
| AC-06 | 有效、无效、重复记录混合 | 有效记录继续处理，计数可核对，不误报成功 |
| AC-07 | 本地三份 JSON 样例的脱敏等价数据 | 文件/文本入口与 OIDC 批量入口给出一致且合理的识别结果 |
| AC-08 | Builder ID 和 IAM SSO 浏览器授权成功 | 自动轮询完成，保存账户并更新列表 |
| AC-09 | Google 和 GitHub 浏览器授权成功 | 当前会话接受有效回调，仅兑换、添加一次 |
| AC-10 | 取消、拒绝、超时、启动失败后重试 | 状态退出等待，可重新开始，无旧结果写入 |
| AC-11 | 快速回调、重复回调、错误 state、旧会话回调 | 有效当前会话不丢失；其他回调拒绝且不破坏当前会话 |
| AC-12 | Windows 安装包与开发模式 | 分别验证实际完成链路，不能只靠离线模拟判定通过 |

## 5. 实施边界

不扩展到账户注册、API 代理、机器码修改或其他无关功能。分析与测试使用合成凭证，不提交原始 JSON、不将真实授权码或 Token 写入报告和测试。实际账号授权和远端凭证是否有效属于集成验收，不能从本地结构校验结果推定。
