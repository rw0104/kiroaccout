# Kiro Account Manager v1.8.15

此版本仅保留候选源码与标签记录，未发布安装包。Windows 发布回归未通过，正式修复及下载请查看 [v1.8.16](v1.8.16.md)。以下为该候选版本的功能说明。

新增“Kiro 设置 → 工具自动批准”，可检查所选默认 IDE 或受管实例的权限配置，按需应用、恢复或导出配置模板。本版保留 1.8.13 的账户迁移恢复功能。

此候选调整了跨平台回归测试，但后续 Windows 发布回归仍发现路径规范化问题，未形成正式发布。

## 使用说明

- 选择需要配置的默认 IDE 或受管实例，查看当前权限状态、目标路径及限制规则；仅在主动点击“应用自动批准配置”后写入。
- 应用时补充缺失的无条件 `allow: all` 与 `allow: fs_write`，保留原有规则和其他配置。该配置允许执行命令和修改文件；已有 `deny`、`ask`、条件规则及内置保护仍可能要求确认或阻止执行。
- 写入前备份原配置。当前文件与本次写入结果一致时，可使用“恢复原配置”；文件已被外部修改或事务尚未核对时，不自动覆盖。
- 仅存在 `permissions.json` 时展示其规则并保持只读，不创建会遮蔽原策略的 YAML。可使用“导出配置”保存 YAML 模板，自行核对和迁移。客户端兼容性无法确认时也保持只读。
- 本入口仅管理所选 IDE 的配置。CLI V3 支持 `permissions.yaml`，但此页不直接管理 CLI。应用或恢复后，建议在 Kiro 中新建会话验证实际行为。

## 可靠性改进

- 修正默认客户端版本探测，未发现有效安装时保持只读。
- 按 YAML、JSON 的实际优先级识别权限文件，避免覆盖或遮蔽 JSON 中已有的限制。
- 正确处理默认 IDE 的 `KIRO_HOME` 配置，保持受管实例各自的目标目录。
- 冲突检查和状态刷新完成前持续持有保存锁，防止应用、恢复、普通保存与目标切换重叠。
- 备份读取失败时保留原恢复基线，不将访问失败误判为没有备份。
- 事务记录未保存成功时明确返回失败或待核对状态，避免误报应用或恢复成功。
- 保留 YAML 中大整数的精度和原有规则语义。
- 对权限文件实施读取大小限制，避免超限文件或读取过程中增长造成无界读取。
- 普通设置 JSON 无法加载时，权限检查和模板导出仍可独立使用。
- 应用和恢复保留 UTF-8 BOM、换行及原始配置字节。
- 修正中英文 CLI 兼容性说明，明确当前配置入口的作用范围。
