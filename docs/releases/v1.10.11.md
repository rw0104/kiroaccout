# Kiro Account Manager v1.10.11

修复手动刷新 Token 后缺少明确结果提示，以及并发检测或数据重新加载可能阻止成功续期清除旧错误的问题。

- **手动续期显示本次结果**：账户卡片和列表明确显示访问令牌已刷新，或本次续期的失败原因。按钮停止转圈仅表示操作结束；失败不再只有停止转圈这一反馈。本次操作结果与账户上次确认的状态分别展示。
- **失败后不继续重复操作**：列表刷新在 Token 续期失败时停止，不再紧接着执行可能再次触发续期的状态查询。
- **保留待合并的成功续期结果**：凭证通知先到、状态结果后到期间，如果另一项检测无法确认账户状态，仍允许成功续期结果完成合并。相同凭证和相同账户状态的数据重新加载也保留合并资格；已确认的新状态和新的登录凭证仍会淘汰过时结果。明确封禁不会被纯 Token 续期成功清除。
- **补齐脱敏诊断**：手动续期失败记录有限的错误分类；后台每批汇总失败次数，区分 HTTP 状态、可识别的服务错误码及 JSON、HTML 或未知响应格式。诊断不记录账户标识、请求地址、凭证或服务原始响应，不将普通 403 自动判定为封禁或刷新凭证失效。

## 验证范围

离线回归覆盖真实卡片和列表操作入口、主进程凭证通知、账户存储动作、并发检测、重新加载，以及失败诊断的白名单与数量上限。发布流水线在 Windows、macOS Intel / Apple Silicon、Linux 执行单元测试、TypeScript 检查、生产编译、打包和校验和验证。

Social 续期请求已静态对照官方签名的 Kiro IDE 1.5.49 / authentication 1.1.1191：未发现端点、POST 请求体或必填业务字段需要迁移，因此本版本没有猜测性更改认证协议、请求身份或自动重试策略。

**本版本修复操作反馈和本地状态合并，不保证解决上游 HTTP 403。** 通用 403 的具体原因仍需结合本次响应分类判断；使用合成无效凭证进行的负向探测不代表真实账户验证。本轮未对真实账户执行自动化登录或续期，也未进行桌面实机验收。

## 下载与升级

提供 Windows x64 安装器与 ZIP、macOS Intel / Apple Silicon 的 DMG 与 ZIP、Linux x64 的 AppImage 与 DEB，并附各平台及汇总 SHA256。Windows 正式版包含自动更新所需的安装器、blockmap 和更新清单；macOS / Linux 请手动升级。

升级前备份账户资料并退出旧管理器；同一系统用户下的新旧版本共享应用数据，不能通过改安装目录或使用 ZIP 实现数据隔离。升级后，点击账户卡片的钥匙按钮可查看一次明确的 Token 续期结果；“访问令牌已刷新”不等于账户用量与健康状态均已重新确认。

受管 IDE 多开、原生 CLI / Crew 连接和 Crew 模型修复仍仅支持 Windows。macOS 使用临时签名，未经 Apple 公证；首次打开和签名说明见 [macOS 安装说明](v1.10.9.md#macos-首次打开)。
