# Kiro Account Manager v1.10.9

修复账户详情和 Kiro 设置中的模型目录显示，保留服务已经返回的模型条目，并补齐企业账户查询模型时的 profile 传递。

- **保留服务返回的模型**：账户详情和 Kiro 设置不再因模型的来源范围或状态元数据再次隐藏条目。保留有效模型标识、服务顺序及已有展示元数据，重复标识保留第一次返回的条目；目录随所选账户的服务响应更新，不维护固定模型名单。
- **补齐企业账户 profile**：账户详情优先使用账户已指定的 profile；没有顶层值时，使用登录凭证中保存的 profile，避免已登录的企业账户因丢失该字段而无法查询模型。
- **profile 变化后重新加载**：详情窗口打开期间，凭证中的 profile 发生变化会重新请求对应模型列表；旧请求稍后返回时不会覆盖新列表。

本次修复针对管理器的目录展示和已选身份传递。模型是否可以实际调用仍由账户、组织授权、服务状态及相应调用规则决定；列表中出现某个模型不等于已经获得推理权限。代理推理准入、代理模型过滤和后备模型选择保留既有检查。

## 验证范围与平台支持

目录展示规则已对照官方 Kiro IDE 1.5.11 的模型响应映射和选择器实现。离线回归覆盖实际账户详情、preload、主进程模型查询及分页请求链路，包括空来源范围、其他状态、重复条目、profile 切换和延迟返回。请求传输使用合成响应；没有读取真实账户或发送认证、刷新、推理请求。相关定向回归、全量离线测试、主进程及界面类型检查、生产编译已通过。各平台构建任务继续执行离线回归、打包、内容检查和校验和生成，完整附件以本 Release 为准。

**Claude Fable 5.1 在真实企业账户中的显示和推理尚未完成本次验收。** 已确认并修复的是服务返回条目被管理器本地过滤的问题，尚未取得该账户的真实模型响应来确认其具体缺失原因。本版本不承诺所有 Fable 5.1 缺失情形均已解决；服务没有返回的模型不会被自动补入。真实账户登录、Token 续期、多窗口并发和桌面实机仍保留此前的验收边界。

本次目录与 profile 修复适用于 Windows、macOS Intel / Apple Silicon 和 Linux。受管 IDE 多开、新版原生 CLI / Crew 账户连接和 Crew 模型修复仍仅支持 Windows；已验证的原生连接版本为官方 CLI 3.1.0 / 3.2.1、Crew 0.12.0 / 0.12.2，本次没有扩展客户端版本范围。

macOS 沿用临时签名（ad-hoc）与强化运行时配置，并在打包检查中验证签名完整性及原生 TLS 库来源；没有 Developer ID 身份签名，也未经 Apple 公证。临时签名不代表 Gatekeeper 信任。

## 下载与升级

提供 Windows x64 安装器与 ZIP、macOS Intel / Apple Silicon 的 DMG 与 ZIP、Linux x64 的 AppImage 与 DEB，并附各平台和汇总 SHA256 校验文件。Windows 正式更新包含安装器、blockmap 和更新清单；macOS / Linux 请手动升级。

升级前备份账户资料并退出旧管理器。新旧版本在同一系统用户下共享应用数据，改安装目录或使用 ZIP 不会实现数据隔离，请勿同时运行。跨机器迁移登录信息时，需要在导出窗口明确勾选“包含登录凭证”，并妥善保存生成的明文文件。

较旧版本若仍运行独立 Crew 工作区，请先停止它；旧数据保留。旧 CLI 绑定升级到 1.10.3 及以后版本时，请关闭 CLI，再显式重新连接一次，以采用已修复的 Social 提供商格式和 profile 存储。使用旧 CLI / 两者切号前，先停止新 CLI 同步。

### macOS 首次打开

1. Apple 芯片选择 `arm64-mac.dmg`，Intel 选择 `x64-mac.dmg`；需要 macOS 13 或更高版本。
2. 下载对应的 `SHA256SUMS-darwin-arm64.txt` 或 `SHA256SUMS-darwin-x64.txt`，使用 `shasum -a 256 <DMG文件名>` 核对下载文件。
3. 退出旧管理器并备份资料后，打开 DMG，将 **Kiro Account Manager** 拖入“应用程序”。
4. 临时签名只验证应用完整性，不代表 Gatekeeper 信任。首次打开若被拦截，请按系统提示在“系统设置 → 隐私与安全性”选择“仍要打开”；参见 [Apple 官方说明](https://support.apple.com/zh-cn/102445)。

如果仍提示“已损坏”，且已确认下载来自本仓库、SHA256 相符，可先校验应用签名，再只移除该应用的下载隔离标记：

```bash
codesign --verify --deep --strict "/Applications/Kiro Account Manager.app" &&
xattr -dr com.apple.quarantine "/Applications/Kiro Account Manager.app"
```

签名校验失败时请重新下载，不要继续处理该副本。此操作不会使应用获得 Apple 公证；安装在其他目录时，请把两处路径替换为实际应用路径。
