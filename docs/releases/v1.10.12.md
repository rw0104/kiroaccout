# Kiro Account Manager v1.10.12

修复续期失败后，多个自动任务仍以高并发重复提交同一批凭证的问题。共享续期服务现在控制失败冷却和恢复尝试，减少暂时拒绝期间的重复请求。

- **失败自动冷却**：同一凭证连续失败后逐步延长等待时间，最长30分钟；主进程、界面自动任务及代理请求共用该状态，不会因为更换调用入口而绕过。成功续期后清除相应失败冷却。
- **控制 Social 续期并发与恢复**：同一网络路径的 Social 续期最多4个同时请求。连续收到多账户的 HTML 403 后，暂缓队列中的其他请求；等待后只允许一次恢复尝试，仍被拒绝则延长冷却。正常认证响应可证明路径恢复，但不会把失败凭证或异常账户标成正常。持续限流或服务故障也不会重新放出整批请求。
- **保留安全的人工重试**：账户卡片钥匙及列表单账户刷新可明确请求一次重试；自动、托盘及批量路径继续遵守冷却。人工操作仍不能重放结果不确定、已经轮换或正在处理的旧凭证。
- **暂停开关不被旧数据恢复**：用户明确修改自动刷新开关或间隔后，凭证更新触发的旧存储读取不再覆盖这些设置。首次启动仍按已保存的偏好加载。
- **修复账户专属代理失效路径**：错误状态、未进入反代池或重新同步的账户，续期仍使用其有效的已保存代理绑定；禁用、删除和解绑的代理不会从陈旧内存数据复活。全局代理和系统代理的既有优先级保持不变。
- **区分延后与实际失败**：脱敏诊断明确标记被冷却延后的调用，避免把它误解为又发出一次 HTTP 请求。相同代理连接池重建不会清空冷却；不同代理路径相互独立。

## 验证范围

使用真实自动调度入口、共享续期服务、假时钟与229份合成凭证进行15分钟回归：持续HTML403条件下，错开的自动任务由4122次模拟POST、峰值并发100，降至15次模拟POST、峰值并发4。结果不确定的请求仍不重放。回归另覆盖代理连接重建、队列与缓存上限、恢复探针、JSON限流/服务错误、旧轮换结果、单账户人工重试及暂停开关重载。

失败冷却行为对照了官方签名的 Kiro IDE 1.5.49 / authentication 1.1.1191。没有改变 Social 认证端点、请求体或客户端身份。测试及打包在 Windows、macOS Intel / Apple Silicon 和 Linux 执行，包含 TypeScript 检查、生产编译、包内容与校验和验证。

本版本修复已确认的客户端请求放大行为；临时拒绝的具体服务端规则和阈值仍未知，也不保证修复所有HTTP403。真实凭证失效仍需重新授权，服务端限制或网络出口问题仍可能影响续期。

## 下载与升级

提供 Windows x64 安装器与ZIP、macOS Intel / Apple Silicon 的DMG与ZIP、Linux x64 的AppImage与DEB，以及各平台和汇总SHA256。Windows正式版包含安装器、blockmap和自动更新清单；macOS / Linux请手动升级。

升级前备份资料并退出旧管理器。同一系统用户下的新旧版本共享应用数据，不要同时运行。此前为排查而关闭的自动开关会保持原设置；确认单账户续期恢复后，可按需重新开启自动刷新。等待恢复期间无需反复批量点击刷新，也不必仅因一次通用403重新导入全部凭证。

受管IDE多开、原生CLI / Crew连接仍仅支持Windows。macOS使用临时签名，未经Apple公证；首次打开说明见 [macOS安装说明](v1.10.9.md#macos-首次打开)。
