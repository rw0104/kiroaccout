# Kiro Account Manager v1.10.0

账户卡和列表的电源按钮现在先显示客户端选择窗口，每次默认 Kiro IDE。IDE 继续使用原有切号流程；当前账户也可以选择其他客户端，原退出登录入口保留。

- **Windows CLI/Crew 连接**：支持已核验的官方 Kiro CLI 3.1.0 和 KiroCrew 0.12.0。自动查找安装位置，也可以手动选择官方程序；未知版本不会直接写入凭证。此操作不自动打开、安装或重启客户端。
- **保留管理器登录与刷新**：新连接只向目标提供短期访问凭证，不复制管理器的 refreshToken、客户端密钥或刷新权限，不更改原自动刷新设置。保持管理器运行；管理器原有刷新产生新凭证后会继续同步。原自动刷新关闭或主访问凭证尚未就绪时，客户端访问可能暂停，需要用户在管理器中处理。
- **账号主体保护**：连接按官方账号主体识别，不能把编辑同一条记录后换成另一个账号误认为普通 Token 更新。目标被外部登录、注销或配置更改时停止自动覆盖；切换真实账号前应正常关闭客户端及后台会话。
- **Crew 独立认证**：使用该版本官方内置 KAS 引擎和加密认证存储，避开 CLI relay 的认证归属差异。首次连接会启用对应的官方引擎选项，并保留其他设置；本地覆盖配置选择了其他引擎时拒绝写入，不覆盖用户选择。
- **停止同步**：选择已连接的 CLI/Crew 后可以停止同步。此操作不退出管理器账号，也不删除客户端数据；目标现有短期凭证自然到期。启用新 CLI 同步期间，旧 CLI/“两者”切号写入会被阻止，停止同步后可继续使用旧入口。
- **状态与并发保护**：凭证写入、连接设置变化和不确定的提交结果分别处理；安装更新、配置变化和失效的异步操作不会继续沿用旧目标。CLI 正常补写空字段和遥测信息不再被误判为换号。

本版新增客户端连接目前面向 Windows 本机客户端；不代表远程 Crew Gateway、WSL 或其他独立运行环境的账号已经切换。macOS/Linux 继续提供现有管理功能与 IDE 切号，新增 CLI/Crew 连接尚未开放。受管 IDE 实例的独占凭证规则保持，已有实例绑定的账户需要按原流程处理。

验证覆盖离线账号/并发/IPC/存储回归、真实界面交互，以及 Windows 上一个真实 Builder ID 账号的 CLI/Crew 访问和模型请求。CLI 已在同一进程中验证跨过保守缩短的目标凭证有效期后继续请求；这不等于所有提供商或上游撤销场景均已实机验证。其他登录提供商的新增路径仍以本地格式和合成凭证回归为主。

升级前备份完整账户数据目录并退出旧版管理器。不同安装目录或 ZIP 不会隔离管理器数据，请勿同时运行新旧版本。macOS 安装包未签名及公证；macOS/Linux 请手动升级。
