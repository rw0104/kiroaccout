# v1.8.0 · Windows x64

本版新增单程序、多配置的 Kiro 客户端实例管理。实际发布附件及校验结果以本 Release 和构建日志为准。

## 本次变化

- 多个实例共用一份官方 Kiro.exe，各自保存 user data、home、扩展、shared data、Agent 数据/插件和临时文件，无需额外 Windows 用户、重复安装或系统密码。
- 创建时选择管理器内已有账户，启动时将其有效凭证写入对应实例缓存。绑定期间实例独占该账户刷新，管理器拒绝重复绑定、刷新和切号；停止并同步最新凭证后才移除绑定，防止轮换和身份串写。
- 新增运行状态、正常停止、重启和管理器重启后的实例识别。按 Windows SID、EXE、实例目录参数、PID 和创建时间核验归属；无法确认时拒绝启停，不按进程名批量操作。
- 停止请求正常关闭窗口。未保存编辑可能阻止退出，此时保持运行，不自动强杀或启动第二份；意外退出可手动重新启动。
- 缓存丢失、过期或 IDE 改登后无法同步时，可停止实例并显式确认“恢复解绑”：保留所有实例文件，不导入未核验凭证，原账户需重新授权，避免永久无法解绑。
- 管理器不再在启动、退出或安装时注册/注销官方 kiro://。Google/GitHub 快捷入口改用门户 PKCE 和本地 HTTP 回调；旧 Builder 设备流与 IAM loopback 兼容入口保留。
- 延续完整备份/精简凭证 JSON、全部/选中及默认无凭证规则，以及刷新防并发覆盖和 Runtime 流解析修复。

## 使用

进入“Kiro 隔离多开”，选择已安装的官方 Kiro.exe、实例名称和已有账户，创建后启动。多个实例可选同一 EXE，每个实例选择不同账户。启动只向该实例专用缓存写入所选凭证，无需全局切号或重新登录；访问凭证过期可由实例自行续期，刷新凭证或 IdC 客户端登记失效需重新授权。启动前只读比较默认 IDE 凭证，发现共用时拒绝，不复制或改写默认缓存。页面提供状态、停止和重启；先停止并同步最新凭证再移除绑定，实例文件仍保留。高级空白实例只用于独立启动或另行授权。

默认必须选择账户，空白实例需明确选择高级选项。正常移除同步失败时，可在确认实例及其子进程都已停止后使用“恢复解绑”并再次确认。该操作会将原账户标记为需重新授权，不把无法核验的实例凭证覆盖回管理器。

1.7.7-rc.1 的 Windows 用户配置已停用，不能自动当作新实例执行；移除旧配置后按新方式创建，旧用户资料不会被删除。

升级前备份资料。默认无凭证 JSON 只能恢复账户资料，迁移登录信息需明确勾选包含凭证并保护明文文件。安装到其他目录或使用 ZIP 不会隔离新旧账户管理器自身，不要同时运行两版。

## 验证与边界

账户绑定、专用缓存写入、轮换身份校验及刷新归属保护已用合成数据回归。在官方 Kiro 1.4.5 上已实机验证：同一 EXE、同一 Windows 用户的两个空白实例并行运行，停止或重启 A 时 B 的完整进程身份保持，新控制器从持久配置恢复两个运行实例，最终正常停止两者。未对默认 IDE 执行启停。

本地 **273 项离线回归全部通过**，Node/渲染层类型检查及生产构建通过。包内容、附件和发布结果以本版本构建日志及本地开发资料不随公开仓库发布为准。双真实账户直接启动及刷新尚未验收；扫码授权、真实未保存提示、异常崩溃和安装升级也没有执行，不标记通过。

按官方 1.4.13 的新 ControlPlane 协议完成一次真实只读身份查询，HTTP 200 且成功取得用户身份；未刷新凭证或写入认证缓存。此结果仅覆盖该单会话，不能替代双账户轮换验收。

多开启动与本地存储依据为官方 Kiro 1.4.13 / Agent 1.1.530 静态证据；已有 Runtime 文本、合成工具事件及功能配置 HTTP 200 记录来自 1.4.5 下的单个 Social 会话，不代表全部最新协议、渠道、模型或区域均通过。

系统网络、代理、证书、Windows 身份和 DPAPI 仍共享，不是安全沙箱。非 Portable 官方 Kiro 启动可能重写同一个 kiro:// 注册值；管理器先验证现有归属与目标 EXE 一致，不一致则拒绝启动。外部协议链接仍进入默认配置，受管网页登录使用自己的本地回调。不得在旧管理器或其他客户端并行刷新同一账户；本版锁不能约束外部程序。实例自行改登不同账户时，不能盲目覆盖原绑定账户。
