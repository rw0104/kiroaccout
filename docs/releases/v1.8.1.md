# v1.8.1 · Windows x64

本版修复 1.8.0 多开功能的三个直接问题：主机 Kiro 安装位置发现、旧版 OIDC 凭证识别，以及实例级代理配置。

## 修复内容

- “Kiro 隔离多开”打开时只读扫描运行中的 Kiro 进程、Windows App Paths/卸载注册表和常见安装目录，逐个通过官方签名与产品校验，自动填充首个有效 `Kiro.exe`；手动选择仍可用。
- 批量 JSON 兼容旧版大小写、snake/kebab 字段、有限凭证容器、`OIDC`/`IdC`/`Builder ID`/`awsidc`/`external_idp` 以及常见 `OLDC` 拼写。未知 provider 继续拒绝，Google/GitHub 不会被误判为 OIDC。
- 兼容旧账户记录中 provider 在顶层、authMethod 过期的情况：启动实例时按已识别 provider 修复内存中的认证链路，避免 Social 账户误走 OIDC 登记校验。
- 创建实例时可填写代理，停止后可修改或清除；支持 `http`、`https`、`socks4`、`socks5`。只注入对应实例，不修改管理器全局代理；代理凭证不会进入日志。
- 后台凭证同步不再使正常实例在界面轮询时短暂显示“状态无法确认”。

## 验证

- 单元回归 **285 项通过**，包含安装发现、OIDC 别名、实例代理、生命周期状态和账户绑定测试。
- Node/渲染层类型检查通过。
- 当前主机只读发现实测找到 `D:\Kiro\Kiro.exe`，版本 `1.4.5`；没有停止或修改默认 Kiro 客户端。
- OIDC 识别使用脱敏/合成 JSON 回归；没有把缺少真实 OIDC 客户端登记有效期的凭证强行标记为可用。

双真实账户同时启动和轮换仍需用户使用独立账户验收；同一账户不要在旧管理器、默认 IDE 和受管实例之间并发刷新。
