# v1.7.7-rc.1 · Windows x64 候选版

本版用于验收 Kiro 客户端多开、JSON 导出和当前客户端请求适配。**它是预发布候选版，不替代正式版 1.7.6，不标记为 latest，也不向稳定版用户推送自动更新。** 候选版 Runtime 最小请求已实测通过，门户授权和跨 Windows 用户 GUI 尚未实测。

## 本次变化

- 新增独立的“Kiro 隔离多开”页面，使用不同的普通 Windows 本地用户配置 Kiro 客户端实例。创建及启动前验证用户 SID、配置目录、安装路径和官方数字签名；通过系统 `runas /profile` 发起启动，不复制账户、不保存密码。仅记录启动请求，不提供结束进程或删除用户资料操作。
- JSON 导出支持全部/选中、完整备份和精简凭证格式，保留提供商、认证方式、区域及分组标签关系。默认无凭证，移除 Token、密码、客户端密钥及已知旧授权字段；含凭证导出必须明确勾选。写入错误与取消分别处理，不误报成功。
- 根据官方 Kiro IDE 1.4.5 / Agent 1.1.499 发行包证据接入统一网页登录门户，使用 PKCE、本地 HTTP 回调和实际提供商身份。旧入口保留为显式兼容方式；门户登录不依赖共享的 `kiro://` 回调。
- 登录后的账户资料查询失败可重试，不额外兑换或刷新已有凭证。保存 OIDC 客户端注册到期时间，接近到期时要求重新登录；导入导出保留其 Unix 秒单位。
- 手动、校验与后台刷新共享同凭证协调逻辑，跟踪轮换代际并阻止迟到结果覆盖新凭证；增加超时、成功响应校验和脱敏错误，刷新 POST 不自动重放。
- AI 主请求适配区域化 Kiro Runtime 的实际 `awsJson1_0` 协议，校验 AWS event stream 的 CRC、分帧、截断和错误事件，处理首包/空闲超时及取消。移除盲目跨端点、账户或签名重放，降低重复消费和重复输出风险。

## 使用前准备

升级前先备份原有资料。默认无凭证 JSON 只能恢复账户资料；要保留登录信息，明确勾选“包含登录凭证”，并保护生成的明文文件。安装到其他目录或解压 ZIP 不会隔离账户管理器自身，不要同时运行新旧管理器。

Kiro 多开需先在 Windows 设置中创建普通本地用户、登录一次初始化其配置目录，并在该用户中安装官方 Kiro。每个 SID 仅配置一个实例，使用分别授权的账户。管理器必须能读取目标安装文件以校验路径和签名；权限不足或验证失败会拒绝启动。启动时在系统窗口输入密码，Windows PIN 不等同于密码。

多开不隔离系统网络、机器级代理或证书，不是虚拟机沙箱，也不隔离现有账户管理器与旧版资料。Secondary Logon 服务、目录访问、密码输入和实际窗口启动仍需在独立环境验收。

- `kiro-account-manager-1.7.7-rc.1-x64-setup.exe`
- `kiro-account-manager-1.7.7-rc.1-x64-windows.zip`

RC 不公开 `latest.yml` 或稳定更新 blockmap。账户管理器安装包未配置发布者代码签名；这与多开时要求目标官方 Kiro 具有有效签名是两项独立检查。

当前已完成 **180/180 项离线回归**。类型检查、编译、打包、包内容、附件摘要及发布结果以本版本构建日志为准；测试数量不代替实机验收。

官方服务配置控制的 `/v1/responses` SSE 路径尚未启用；其他模型管理、订阅和管理端请求未在本轮全面迁移。已实现的 Runtime 路径不代表所有账户、区域或未来服务配置均已验收。
