# v1.8.2 · Windows x64

本版修复多开实例改写原账户资料、启动准备失败后仍锁定账户，以及删除未保存却从界面消失的问题。

## 修复内容

- 复制凭据和规范化启动配置不再写回原账户的提供商、登录方式、profile 或 OIDC 登记资料。核验后的实际凭据变化仅同步 Token 和到期时间；明确冲突的提供商资料会在启动前被拒绝。
- 新建实例只记录账户选择，不占用原账户。首次启动准备失败且确认客户端未启动时释放账户，配置可直接移除；实际启动请求发出后保留凭据归属，避免两端并发续期。
- 首次准备失败后重试，会从管理器的最新凭据重新复制；已轮换或来源不明的实例缓存不会被覆盖。失败回滚也会恢复原先仍符合条件的代理池账户。
- 因实例归属或进行中的账户操作而拒绝刷新时，不再将健康账户标记为错误，不覆盖原错误信息和检查时间。界面的临时“刷新中”状态独立保存，期间其他写入不会将它存入账户库。
- 删除账户须等待后台确认保存后才移除界面行。保存被拒绝时保留账户并显示原因；批量删除和关联结果清理也等待确认。串行保存防止延迟写入重新带回已删除账户。
- 实例页面明确显示尚未交接的账户选择，并调整创建、启动和解绑提示。

## 验证与升级说明

- 合成账户与隔离目录下的离线单元回归 **327 项全部通过**，包含真实主进程保存入口、刷新归属、缓存重试、删除确认、状态恢复和刷新期间的交叉保存。
- Node 与渲染层类型检查、生产构建通过。
- 本轮未执行真实客户端启动或双真实账户登录、续期验收。

本版不会自动恢复已经失效的凭据，也不会自动解除旧实例的账户归属。旧绑定请先停止实例并正常同步、移除；无法核验缓存时，可按界面说明执行恢复解绑并重新授权。同一账户仍不应由旧管理器、默认 IDE 和受管实例同时刷新。
