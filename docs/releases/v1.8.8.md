# v1.8.8 · 修复账户卡片刷新 HTTP 400

本版修复旧账户在“账户管理”卡片上手动点击刷新后显示 `Kiro account service: request_failed (HTTP 400)` 的问题。

## 修复内容

- 账户状态和额度查询对齐当前 Kiro ControlPlane 请求：使用 AWS JSON 1.0 的 POST `/`，请求体发送 `origin` 和已解析的 `profileArn`。
- 旧的 Google、GitHub 和 Builder ID 账户缺少 profile 时，使用官方客户端对应的个人默认 profile；已有真实组织 profile 和区域保持不变。
- 统一旧账户的 provider/authMethod 识别，避免 Social 账户被误走 IdC 请求头。
- 仅在服务明确报告 Token 无效或过期时执行一次刷新；profile 校验失败和普通权限拒绝不会重复刷新。
- 刷新成功但后续状态查询失败时，仍保存已经轮换的凭证，避免丢失新的 refresh token。
- 模型目录和实例身份核验共用同一套 profile 解析规则。

## 验证范围

- 490 个离线单元测试通过。
- TypeScript 类型检查和 Electron 生产构建通过。
- 未启动现有客户端，未使用真实账户执行刷新或状态查询；真实账户验收仍需在独立测试环境完成。
