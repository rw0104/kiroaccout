# Kiro Account Manager v1.10.10

修复账户状态误判、批量检测统计和续期后旧错误延迟消失的问题。

- **区分令牌过期、封禁和查询失败**：账户服务以 HTTP 400 返回明确的 token 原因时，正确提示访问令牌需要刷新；手动检查按既有流程续期并重试。批量检测继续只查询状态，不自动续期。明确封禁仍显示异常，通用 403、超时及其他无法确认账户状态的失败保留上次状态，并标记为上次结果。
- **补齐批量查询的 profile**：优先传递账户已指定的 profile，缺少时使用凭证中保存的值，兼容仅保存其中一个字段的旧账户。缺少 profile 的查询失败不再被当成令牌失效或封禁。
- **纠正批量完成统计**：查询失败计入失败数量；续期已成功但后续状态查询失败时，仍保存新凭证，避免丢失已轮换的登录信息。
- **及时合并续期后的状态**：主进程先推送凭证、后返回状态结果时，界面正确合并两次结果并保留已经写入的绝对到期时间。其间修改分组、标签或其他账户资料也能正常完成合并；重复和过时的结果不会覆盖较新的状态。
- **保留无法确认的续期状态**：未明确证明刷新凭证失效的服务错误保留账户上次状态。明确的凭证失效仍提示重新授权。

## 验证范围与平台支持

本次修复针对管理器的错误分类、参数传递、批量计数和本地状态合并。离线回归使用合成请求响应和隔离目录，覆盖结构化 HTTP 400、通用 403、超时、封禁、旧记录 profile、部分成功续期，以及凭证通知与状态结果乱序、重复和资料编辑。发布前执行全量单元测试、主进程和界面 TypeScript 检查、生产编译；各平台构建任务继续执行离线回归、打包、内容检查和校验和验证。

通用 HTTP 403 的上游原因尚未确认。本次未对真实账户执行登录、续期或批量检测，也未进行桌面实机验收；离线验证不代表所有线上账户故障均已解决。最新官方客户端的请求兼容性仍以已经核验的链路为限，本版本不扩大此前声明的客户端兼容范围。

账户状态修复适用于 Windows、macOS Intel / Apple Silicon 和 Linux。受管 IDE 多开、原生 CLI / Crew 账户连接和 Crew 模型修复仍仅支持 Windows。macOS 安装包沿用临时签名（ad-hoc），没有 Developer ID 身份签名，也未经 Apple 公证。

## 下载与升级

提供 Windows x64 安装器与 ZIP、macOS Intel / Apple Silicon 的 DMG 与 ZIP、Linux x64 的 AppImage 与 DEB，并附各平台和汇总 SHA256 校验文件。Windows 正式更新包含安装器、blockmap 和更新清单；macOS / Linux 请手动升级。

升级前备份账户资料并退出旧管理器。新旧版本在同一系统用户下共享应用数据，改安装目录或使用 ZIP 不会实现数据隔离，请勿同时运行。安装后可重新执行账户检查；若明确提示访问令牌过期，请执行续期，若明确提示刷新凭证失效则需重新授权。无法确认状态的失败会保留上次结果，请结合提示重试。

跨机器迁移登录信息时，需要在导出窗口明确勾选“包含登录凭证”，并妥善保存生成的明文文件。旧 CLI 绑定升级到 1.10.3 及以后版本时，请关闭 CLI 后显式重新连接一次。macOS 首次打开和签名说明见 [macOS 安装说明](v1.10.9.md#macos-首次打开)。
