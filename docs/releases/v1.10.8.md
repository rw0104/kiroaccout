# Kiro Account Manager v1.10.8

适配官方 Kiro IDE 1.5.11，更新网页登录与登录凭证有效期处理，修复默认 IDE 账户同步和设置显示。macOS Intel / Apple Silicon 与 Windows、Linux 使用同一套本次更新的登录和设置逻辑。

- **Google / GitHub 网页登录**：快捷入口在 Kiro 门户中显示对应的登录方式；授权码交换和 Social 刷新采用与已核对的 IDE 1.5.11 一致的客户端标识。门户继续使用本地 HTTP 回调，不占用官方 IDE 的 `kiro://` 协议。
- **保留 OIDC 登记有效期**：直接 Builder ID 和 IAM SSO 登录保存服务返回的客户端登记到期时间，并拒绝已过期或格式无效的登记响应。客户端登记、设备授权和访问令牌的期限分别处理。登录回调结果按实际剩余期限交付，避免等待界面取结果延长凭证有效期。
- **减少登录后的重复刷新**：直接 Builder ID / IAM SSO 登录已返回有效访问令牌及其期限时，使用首次签发的凭证验证账户，不再立即进行一次多余换发。未提供有效访问期限时保留原有换发验证途径。
- **完整写入默认 IDE 登录缓存**：使用同目录临时文件后替换，避免其他窗口读取到写入一半的 Token 文件；针对 Windows 短暂文件占用进行有限重试。后台续期仅在磁盘凭证仍属于所观察的账户和代次时发布，发现外部切号或退出登录则跳过写入。
- **核对反向同步的账户归属**：不再仅凭“上次切换账户”认领 IDE 新写入的凭证。同步核对已有凭证及登记信息，跳过无法证明归属、已被替换或在核对期间发生变化的结果，并保留受管实例绑定和恢复解绑保护。这些检查减少并发覆盖风险，不保证跨进程写入完全互斥。
- **跟随新版 Memory 设置入口**：Kiro IDE 1.4.236 及以后版本在 Memories 侧栏齿轮中管理记忆模式，管理器显示对应操作说明；较早版本保留已有选择器。未识别版本时不会擅自写入新版已停用的 Memory 设置。
- **更正初始模型与忽略文件设置**：区分未配置的初始模型和显式选择，支持清除管理器设置的初始模型。忽略文件使用官方支持的文件名列表，拒绝路径和通配模式，保留其他设置及旧字段。初始模型设置不代表当前聊天实际使用的模型。
- **继承 macOS 打包修复**：应用使用临时签名（ad-hoc）及强化运行时配置，许可证放入应用资源目录；打包检查验证签名完整性和原生 TLS 库来源。没有 Developer ID 身份签名，也未经 Apple 公证。

## 验证范围与平台支持

本次适配依据官方 Kiro IDE 1.5.11 的客户端实现及 AWS 官方 OIDC 字段合约；Windows、Linux 和 macOS 双架构的相关认证、Agent 和设置代码已作静态对照。离线回归覆盖实际登录入口、回调有效期、缓存写入和账户归属，以及设置读写；类型检查和生产编译已通过。安装包由各平台构建任务执行离线回归、编译、包内容检查和校验和生成，完整附件以本 Release 为准。

**真实账户登录、Token 续期、多窗口并发及桌面实机尚未完成本次验收。** 直接 OIDC 的 Kiro 特定权限范围与实际授权可用性也未通过独立真实账户验证；字段有效期修复不代表这些链路已经完成实机验收。合成数据测试不等同于 Windows 文件占用或多个实际客户端同时更新缓存的验证。

受管 IDE 多开、新版原生 CLI / Crew 账户连接和 Crew 模型修复仍仅支持 Windows。已验证的原生连接版本为官方 CLI 3.1.0 / 3.2.1、Crew 0.12.0 / 0.12.2。本次不扩展这些客户端的版本支持范围。macOS / Linux 保留网页登录、普通 IDE 账户切换和既有账户管理功能。

## 下载与升级

提供 Windows x64 安装器与 ZIP、macOS Intel / Apple Silicon 的 DMG 与 ZIP、Linux x64 的 AppImage 与 DEB，并附各平台和汇总 SHA256 校验文件。Windows 正式更新包含安装器、blockmap 和更新清单；macOS / Linux 请手动升级。

升级前备份账户资料并退出旧管理器。新旧版本在同一系统用户下共享应用数据，改安装目录或使用 ZIP 不会实现数据隔离，请勿同时运行。跨机器迁移登录信息时，需要在导出窗口明确勾选“包含登录凭证”，并妥善保存生成的明文文件。

较旧版本若仍运行独立 Crew 工作区，请先停止它；旧数据保留。旧 CLI 绑定升级到 1.10.3 及以后版本时，请关闭 CLI，再显式重新连接一次，以采用已修复的 Social 提供商格式和 profile 存储。使用旧 CLI / 两者切号前，先停止新 CLI 同步。

### macOS 首次打开

1. Apple 芯片选择 `arm64-mac.dmg`，Intel 选择 `x64-mac.dmg`；需要 macOS 13 或更高版本。
2. 下载对应的 `SHA256SUMS-darwin-arm64.txt` 或 `SHA256SUMS-darwin-x64.txt`，使用 `shasum -a 256 <DMG文件名>` 核对下载文件。
3. 退出旧管理器并备份资料后，打开 DMG，将 **Kiro Account Manager** 拖入“应用程序”。
4. 临时签名只验证应用完整性，不代表 Gatekeeper 信任。首次打开若被拦截，请按系统提示在“系统设置 → 隐私与安全性”选择“仍要打开”；参见 [Apple 官方说明](https://support.apple.com/zh-cn/102445)。

如果仍提示“已损坏”，且已确认下载来自本仓库、SHA256 相符，可先校验应用签名，再只移除该应用的下载隔离标记：

```bash
codesign --verify --deep --strict "/Applications/Kiro Account Manager.app" &&
xattr -dr com.apple.quarantine "/Applications/Kiro Account Manager.app"
```

签名校验失败时请重新下载，不要继续处理该副本。此操作不会使应用获得 Apple 公证；安装在其他目录时，请把两处路径替换为实际应用路径。
