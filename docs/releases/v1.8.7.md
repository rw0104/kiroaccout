# v1.8.7 · 托盘后台内存优化

本版减少长期后台运行时日志、任务历史、会话及模型缓存的积累，并避免隐藏窗口持续读取整批日志。代理、Token 刷新、自动切号、账户保存、运行中任务和精确 token 计数继续保留。

## 优化与修复

- **近期日志按容量保留**：历史同时限制条数和总字节，单条超长字段保存有限、脱敏的预览并标注截断。保留查看、筛选、复制、导出和清空功能，避免日志引用长期占用完整响应对象。
- **日志改为增量读取**：窗口隐藏或最小化时暂停视觉日志请求，恢复后继续读取新增记录。慢请求不会重复叠加，关闭详情会释放日志快照；详情的显示数量不缩小搜索与导出所用的保留历史范围。
- **任务结束后释放资源**：仅保留最近 200 条完成历史，清理不再需要的控制回调；全部运行中、暂停中的任务及取消控制保持可用。
- **缓存有明确边界**：会话映射使用固定长度散列及真实容量/过期淘汰；模型目录缓存同时按条数和字节限制，过大目录仍正常返回。清空或停止代理后，迟到的目录请求不会重新填满缓存。
- **减少流式副本**：删除未使用的完整响应文本累加，保留全部流式文本、工具调用、usage 和精确计数行为。
- **后台暂停装饰层**：按原生窗口状态停止隐藏窗口的背景装饰，恢复前台后恢复显示；不会暂停后台认证或代理业务。
- **请求并发控制生效**：AI 请求在读取正文前遵守配置的并发上限，突发请求有序等待；超载或等待超时返回可重试的繁忙响应，不将其误判为账户故障。健康、模型与管理入口不被长流式请求阻塞。

## 日志与负载边界

近期日志历史最多约 8 MiB 的序列化数据、单条最多约 32 KiB；这是诊断数据预算，不是整个客户端的内存上限。旧版超大日志保留归档或独立旁路文件，不一次性载入内存；迁移情况会在日志中提示。极端慢磁盘下会限制文件输出排队，并记录未写入文件的数量，近期内存记录仍可查看。

合成日志负载验证了常驻堆和保存峰值下降，不能据此承诺所有机器或整个 Electron 进程获得固定百分比的降幅。后台空闲、代理繁忙和首次加载编码器的内存成本不同。

## 升级与验证范围

升级前备份账户资料，正常退出旧管理器后安装。ZIP 或更换安装目录不会隔离管理器数据，不要同时运行新旧管理器，也不要让多个客户端并发刷新同一账户。

各平台分别通过离线回归、类型检查、生产构建、打包与包内容校验后发布。本轮没有完成完整客户端的真实账户长期后台验收；模块合成测试及独立背景样例不能代替完整桌面实机验证。

Kiro 隔离多开仍仅支持 Windows。macOS 安装包未配置 Apple 开发者签名及公证；Linux 系统代理自动检测及证书安装仍有发行版兼容限制。macOS / Linux 暂不提供自动更新。
