# Kiro Account Manager v1.10.7

客户端按所选目标检查，并在 Kiro 设置中明确展示用户权限文件的模型审核默认值。

- **按需检查客户端**：账户客户端选择器仍每次默认 IDE。打开选择器时直接使用 IDE 切换入口；选择 CLI 后才检查 CLI，选择 Crew 后才检查 Crew 及其模型修复状态。切换选项后，较早检查返回的结果会被忽略，避免慢速 Crew 检查影响其他选项。三个选项都只切换账号，客户端由用户自行打开。
- **CLI 版本提示**：遇到尚未验证本地账号切换的 CLI 版本时，显示检测到的版本和官方 `kiro-cli login` 登录方式。Windows 原生连接继续支持已验证的官方 CLI 3.1.0 / 3.2.1、Crew 0.12.0 / 0.12.2。
- **Memory 选项说明**：记忆设置改为“不使用记忆”“使用记忆并自动创建”“使用记忆，仅在要求时创建”“使用已有记忆（只读）”，对应所选 IDE 的四种已有模式。启用或停用记忆、进入或退出只读模式后需新建会话；两种创建方式之间的切换即时作用于本地会话。CLI 的记忆设置独立管理。
- **保留 MCP 高级配置**：MCP 启用设置保留启用 / 禁用两种选择。编辑本地命令型服务器时保留超时、工具限制等高级字段，以及其他服务器和根配置；远程或其他高级配置通过“用户 MCP 配置”编辑。重复创建、重命名冲突及已经移除或改为非命令型的条目会拒绝保存，打开配置文件失败会显示错误。
- **识别模型审核默认值**：“模型审核 · Approve for me”区域识别用户权限文件中的 `approve-for-me` 预设和无条件 `all` / `evaluate` 规则，并区分未配置和尚未确认的状态。此处显示用户文件配置；工作区或当前聊天可能采用其他模式。
- **区分审核与显式允许**：权限规则区域改名为“显式允许规则”。检测到无条件 `all` 或 `fs_write` 允许规则时，提示命中的操作会优先按规则处理，并在可恢复管理器写入时给出恢复提示。当前聊天可在官方聊天权限菜单选择 Approve for me；新聊天的用户默认值可在 Kiro 命令面板执行 `Kiro: Enable Approve For Me (User)` 设置。

Crew 模型目录修复继续作用于已校验的官方安装，并保留原文件备份。使用前正常关闭官方 Crew 及其后台服务，在 Crew 选项执行“修复模型列表”，然后切换账号、打开官方客户端并创建新会话。官方更新后重新检测，必要时再次修复；“恢复官方文件”同样要求客户端关闭。模型目录和账号可用范围以官方返回为准。

本次验证范围为离线回归、类型检查、编译和安装包内容校验；新增说明不代表新的真实账户登录、刷新或桌面实机验收。原生 CLI / Crew 连接与 Crew 文件修复目前支持上述已验证的 Windows 客户端；macOS / Linux 管理器保留既有功能。账户绑定与轮换保护已有合成数据回归，双真实账户登录及刷新仍待验收。

升级前备份账户资料并退出旧管理器。较旧版本若仍运行独立 Crew 工作区，请先停止它；旧数据保留。旧 CLI 绑定升级到 1.10.3 及以后版本时，请关闭 CLI，再显式重新连接一次，以采用修复后的 Social 提供商格式和 profile 存储。使用旧 CLI / 两者切号前，先停止新 CLI 同步。

完整安装包提供 Windows x64 安装器与 ZIP、macOS Intel / Apple Silicon 的 DMG 与 ZIP、Linux x64 的 AppImage 与 DEB，并附 SHA256 校验文件。Windows 正式更新包含安装器、blockmap 和更新清单。macOS 安装包未签名及公证；macOS / Linux 请手动升级，其真实账户和桌面实机验收尚未完成，多开仅支持 Windows。
