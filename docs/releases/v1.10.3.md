# Kiro Account Manager v1.10.3

修复 Social 账户资料传递与 CLI 模型访问，并增加独立的受管 Crew 工作区。

- **Social 资料保存**：单个凭证添加和本地 IDE 导入保留有效 profile；企业导入保留组织登录地址。正常 Social 续期返回的新 profile 会随同一凭证代次保存，响应省略时保留已有资料。
- **资料冲突提示**：空白 profile 不再遮蔽已保存值；两处有效值冲突仍拒绝。客户端预检分别说明 profile、区域、提供商、认证方式或企业地址问题，Social 不要求填写组织地址。
- **CLI 模型目录**：使用 CLI 3.1.0 所需的小写 Social 提供商标签，并在同一个事务中同步原生模型目录所需的独立 profile 资料。目标资料被外部更改时继续拒绝旧快照，不覆盖其它 CLI 设置。
- **CLI 旧连接迁移**：升级后，已有 CLI 同步绑定需要在客户端关闭时重新连接一次。旧绑定不会自动改写目标，也不会被误判为已采用新格式。
- **Crew 独立工作区**：客户端主列表保留 IDE / Crew / CLI 三项；选择“Kiro Crew”后默认使用“独立工作区”模式，点击“启动并打开”可使用已安装的官方 Crew 0.12.0。“现有客户端”作为次级模式保留，只切换账号，不会启动客户端。兼容修复处理异步到达的模型目录，并通知菜单重新获取；模型列表以该账号的实际服务返回为准。工作区资料独立保存，官方安装目录、默认 Crew 数据和原 Crew 连接保持原样。运行中可打开或停止工作区，退出管理器也会停止自己启动的工作区。
- **更新弹窗排版**：当前版本与新版本分开展示，更新说明按标题、段落和列表呈现；长内容只滚动正文，下载进度及失败阶段更清楚。保留原有主题、透明度和背景效果。

新客户端连接只接收短期访问凭证，不接收管理器的 refreshToken 或客户端密钥。请保持管理器运行，以同步其原有刷新流程产生的新访问凭证；不会另建竞争刷新流程。

真实账号验证范围为 GitHub；Google 使用合成协议与入口回归覆盖。没有将这些结果扩大为所有账号权限、所有客户端版本或长期多轮自然续期的保证。受管 Crew 与 CLI 连接功能当前仅支持上述 Windows 官方版本；macOS/Linux 仍可使用管理器的既有功能。

升级前备份完整账户数据目录并退出旧版管理器。不同安装目录或 ZIP 不会隔离管理器自身的数据，请勿同时运行新旧版本。macOS 安装包未签名及公证；macOS/Linux 请手动升级。
